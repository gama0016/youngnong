# 영농노트 (youngnong)

농촌진흥청 **농사로**(nongsaro.go.kr)에 흩어져 있는 영농 정보를, 실제 농사짓는 사람이 **작목 하나당 한 화면**으로 볼 수 있게 정리한 사이트입니다.

## 화면

| 메뉴 | 내용 |
|---|---|
| 내 농사 | 필지·하우스 동마다 작기 등록(작목, 면적, 심은 날). 농사로 표준 일정을 내 날짜로 옮긴 일정과 본문의 "아주심기 후 20일" 문구로 계산한 날짜, 지금 챙길 일(완료 → 일지), 회차별 비료 포대 수와 자재 준비량, 방제·비료·수확·작업 기록, 수확 전 안전일수 경고, 올해 결산(수확량, 판매 금액, 비용, 소득), **이번 주 영농 정보**(지금 단계·철에 맞는 작업 방법, 병해충, 재해 대비, 이번 비료만 골라 모음) |
| 오늘 | 내 작목의 이번 순 할 일과 **완료** 버튼(누르면 영농일지에 자동 기록, 되돌리기 가능), 지난 순에 놓친 일, 농장 읍·면·동의 나흘 날씨 경보(서리·폭염·많은 비·강한 바람)와 **기상청 기상특보**, 그에 맞는 내 작목 대책(지금 철·생육 단계에 맞는 것만), 순 넘겨 보기, 기본 밭 면적 |
| 작목 | 분류별 목록, 적는 대로 찾는 검색(이름 우선, 꼬추·나락 같은 다른 이름도 인식), 담기 버튼으로 내 작목 등록 |
| 작목 상세 | 재배 환경 기준 → 연간 농작업 달력(폰에서는 시기순 목록) → 단계별 작업 방법 → 비료 주는 양(내 면적으로 환산) → 병해충 → 기상재해 대책 → 원문 링크 |
| 순이익 | 작기 화면의 순이익 칸: 지금까지(판매 − 기록한 비용), 작기 끝까지 예상(예상 수량 × 단가 − 비용), 농사로 평균 소득(내 면적 환산). 단가는 내가 정한 단가 → 지금까지 판 평균 단가 → 농사로 3년 평균 가격 순. 수확 기록에 판매 단가(원/kg)를 적으면 판매 금액이 계산됨. `#/profit`: 연도별 작기별 순이익과 연말 예상(내 수확 일정으로 올해 안에 들어올 몫만) |
| 병해충 도감 | 작목 화면의 병해충 칸과 `#/pest/<작목>/<코드>`. 농사로 「작목별병해충」의 증상·피해, 생기는 조건·생태, 방제 방법, 사진을 원문 그대로. 증상 낱말로 찾기, 병/해충 거르기, 농작업일정에 오른 주요 병해충과 이번 달 발생 표시, 방제 기록으로 바로 가기 |
| 달력 | 월과 순을 고르면 그때 할 작업을 작목별로 (시기·범위·분류·작업 필터) |
| 일지 | 영농일지 기록, 연간 요약, 백업/복원, 엑셀용 파일, **제출용 영농일지**(작업·농약·비료·수확 표를 A4로 인쇄·PDF 저장, 지원사업 정산·GAP 준비용) |
| 말로 기록 | 작업한 것을 말하면(또는 휴대폰 키보드 받아쓰기) 날짜·필지·작업·자재·양으로 정리해 기록. 빠진 것만 기록 화면에서 채움 |
| 더보기 | 비료·농약 계산기(희석량, 밭 전체 물·약·약통 수), 월별 달력, 내 설정(내 지역: 중부·남부·제주·고랭지, 날씨 위치: 시·도 → 시·군·구 → 읍·면·동 또는 이름 찾기, 글자 크기), 비료 계산기(작목별 면적 → 비료 포대 수), 용어 풀이, 농촌진흥청 서비스 바로가기 |

**리프노트(leafnote.kr/nong)로 옮겼습니다.** 리프노트 카카오 계정으로 로그인하면 기록이 계정에 저장되어 기기를 바꿔도 이어집니다. 로그인하지 않아도 이 기기에 저장해 그대로 쓸 수 있습니다(가입·서버 없이 동작). 날씨는 리프노트에서는 기상청 단기예보·기상특보(리프노트 서버가 인증키로 받음), 그 밖의 주소에서는 [Open-Meteo](https://open-meteo.com/) 예보를 받으며, 고른 읍·면·동의 대표 좌표(격자)만 보냅니다. 지역 목록은 기상청 「격자_위경도」 자료(2026-09-30, 공공누리 제1유형)로 만든 `data/regions.json`(시·도 17, 시·군·구 256, 읍·면·동 3,565)입니다. 내 작목·면적·일지는 사용자의 브라우저(localStorage)에만 저장됩니다. 홈 화면에 설치(PWA)할 수 있고, 한 번 열면 통신이 약한 곳에서도 열립니다.

## 배포 (GitHub Pages)

`main` 브랜치에 푸시되면 `.github/workflows/pages.yml` 이 사이트를 GitHub Pages 로 배포합니다.
주소: https://gama0016.github.io/youngnong/

처음 한 번만 저장소에서 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿔 두면 됩니다.
배포 때 `data/crops.json` 을 새로 만들고, 사이트에 필요한 파일(index.html, css, js, icons, assets, data/crops.json 등)만 올립니다.

## 농사로 Open API 연동

`.github/workflows/nongsaro-sync.yml` 이 매주 월요일 새벽(한국 시간)과 수동 실행 때 농사로 Open API(농작업일정)에서 원자료를 받아 `data/raw/` 에 저장하고, 바뀐 것이 있으면 main 에 커밋한 뒤 사이트를 다시 배포합니다.

- 인증키: 저장소 **Settings → Secrets and variables → Actions → New repository secret**, 이름 `NONGSARO_API_KEY`. 키가 없으면 이 워크플로는 아무것도 하지 않고 끝납니다.
- 직접 받기: `NONGSARO_API_KEY=키 node scripts/fetch-nongsaro.mjs` (특정 작목만: `ONLY=30600,30697`)
- 받는 자료: 분류 목록 → 분류별 작목 목록 → 작목별 농작업일정 본문(HTML)과 작형 정보. 키는 어떤 파일에도 저장되지 않습니다.
- 다음 단계: 받은 본문 HTML의 월별 작업 표를 읽어 `data/crops/*.json` 의 달력(상순·중순·하순)을 원문 그대로 채웁니다.

## 실행

빌드 과정이 없는 정적 사이트입니다.

```bash
python3 -m http.server 8000
```

그대로 GitHub Pages 등 정적 호스팅에 올리면 됩니다.

## 구조

```
index.html              화면 틀
css/style.css           스타일 (밝은/어두운 테마, 모바일 우선, 인쇄용)
js/app.js               화면 로직 전부 (해시 라우팅, 의존성 없음)
data/crops/<id>.json    작목별 원자료 (id = 농사로 농작업일정 cntntsNo)
data/crops.json         위 파일들을 합친 번들 — 사이트는 이것만 읽음
data/SCHEMA.md          작목 데이터 형식
scripts/build-data.mjs  data/crops/*.json → data/crops.json
sw.js, manifest.webmanifest   오프라인·설치
```

작목 데이터를 고치거나 추가한 뒤에는 번들을 다시 만듭니다.

```bash
node scripts/build-data.mjs
```

## 농산물 소득 자료

- `scripts/fetch-income.mjs`가 농사로 「농산물소득정보」(농촌진흥청 농산물소득조사, menuId=PS65441)에서 작목별 전국 10a당 총수입·수량·가격(원/kg)·경영비·소득을 최근 3년치 받아 `data/income.json`에 저장한다(GitHub Actions `.github/workflows/income-fetch.yml`). 영농노트 작목과의 연결은 `scripts/income-link.mjs`(같은 작물만, 시설↔노지처럼 상품이 다른 것은 잇지 않음).
- 벼·노지 고추처럼 농진청 소득조사에 없는 작목은 평균 자료가 없어 예상 수량·단가를 직접 적는다.

## 병해충 도감 자료

- `scripts/fetch-pests.mjs`가 농사로 「작목별병해충」(menuId=PS00202) 페이지를 읽어 내 작목과 이름이 같은 작목(같은 작물의 다른 이름 포함, 예: 벼→논벼)의 병·해충 상세를 `data/pests/<농사로 작목코드>.json`에, 이름 대응을 `data/pests/index.json`에 저장한다. 글은 원문 그대로(줄바꿈만 정리), 사진은 국가농작물병해충관리시스템 주소를 그대로 쓴다.
- 농사로 웹은 일부 환경(이 리포의 원격 작업 환경 등)에서 닿지 않아 GitHub Actions(`.github/workflows/pests-fetch.yml`, 수동 실행 또는 스크립트 변경 시)에서 받는다.

## 자료 출처와 한계

- 모든 작목 데이터는 농사로 「농작업일정」 상세 페이지
  (`/portal/ps/psb/psbl/workScheduleDtl.ps?menuId=PS00087&cntntsNo=<id>`)에서 가져왔고, 작목마다 원문 링크가 붙어 있습니다.
- 원문 달력 그림이 읽히지 않아 비는 날짜는, 같은 페이지 본문(단계별 작업의 시기 문구, 병해충 발생 시기)에 글로 적힌 월·순을 `scripts/build-data.mjs` 가 읽어 보완하고 화면에 **추정**으로 표시합니다. 상대 시기(○○ 후 20일 등)는 읽지 않습니다.
- 그 밖에 원문에 없는 값은 채우지 않았습니다. 원문의 월별 작업 도표는 이미지/복잡한 표라 텍스트로 읽히지 않는 경우가 많아, **본문에 시기가 글로 적힌 작업만 달력에 표시**되고 나머지는 "시기 미표기 작업"으로 나옵니다.
- 수집은 페이지를 읽어 구조화하는 방식(자동 추출)이라 옮기는 과정의 오류가 있을 수 있습니다. 공개 전에 주요 작목은 원문과 대조 검수가 필요합니다.
- **이용 조건: 공공누리 제2유형 (출처표시 + 상업적 이용금지).** 유료 서비스·광고 등 상업적 이용을 계획한다면 농촌진흥청과 별도 협의가 필요합니다.

## 다음 단계

1. **농사로 Open API 연동** — 농사로 Open API(인증키 발급 필요)로 농작업일정·품종·병해충·주간농사정보를 정기 수집하면 달력의 빈 시기를 채우고 자료를 자동 갱신할 수 있습니다. API는 등록 도메인·서버 호출이 필요하므로 수집 스크립트(예: GitHub Actions)가 `data/crops/*.json` 을 갱신하는 구조를 권장합니다.
2. **날씨·기상특보 연동** — 필지 위치 기준 예보와 서리·폭염·호우 특보를 "오늘" 화면에, 작목의 재해 대책과 함께.
3. **영농일지 앱 연동** — 현재 일지 데이터(JSON)는 `id / date / crop / work / field / input / hours / cost / memo` 구조라 그대로 서버 동기화로 옮길 수 있습니다. 로그인, 기기 간 동기화, 사진 첨부, 농약 살포 기록(PLS 대응), 필지 관리.
4. **병해충·농약** — 작목별 등록 농약·안전사용기준(농약안전정보시스템), 병해충 발생 예보 연결.
5. **경영** — 일지의 비용·시간을 작목별 소득 분석으로, 농산물 소득자료·도매가격 연결.

## 리프노트와 함께 쓰기 (2026-11-17)

- 서비스 주소는 **https://leafnote.kr/nong/** 이다. 이 리포가 앱의 원본이고, 리프노트 리포의 `npm run nong:import`가
  이 리포의 사이트 파일을 `public/nong/`으로 복사해 함께 배포한다. 앱을 고치면 여기서 고친 뒤 리프노트에서 다시 가져온다.
- 계정·저장: 리프노트의 카카오 로그인 세션을 그대로 쓴다(같은 주소라 별도 로그인 장치가 없다). 기록은 기기(localStorage)에
  먼저 쓰고, 로그인돼 있으면 `GET/PUT /api/nong/data`(리프노트, 회원만)로 문서 한 장을 맞춘다.
  - 설정류(`favs`·`settings`·`areas` 등)는 나중에 바꾼 쪽, 기록류(`diary`·`plantings`·`done`)는 합집합. 지운 것은 `tomb`에 시각을 남겨 되살아나지 않게 한다(180일 뒤 정리).
  - 저장이 겹치면 서버가 409와 서버 문서를 돌려주고, 앱이 합쳐서 다시 보낸다.
  - 칸 목록(`SYNC_KEYS`)을 바꾸면 리프노트 `src/lib/nong.ts`도 같이 바꾼다.
- 옛 주소(gama0016.github.io/youngnong)는 새 주소 안내와 **내 기록 가지고 옮기기**(두 창이 서로 주소를 확인하고 기록을 넘김)를 보여 준다.
