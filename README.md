# 영농노트 (youngnong)

농촌진흥청 **농사로**(nongsaro.go.kr)에 흩어져 있는 영농 정보를, 실제 농사짓는 사람이 **작목 하나당 한 화면**으로 볼 수 있게 정리한 사이트입니다.

## 화면

| 메뉴 | 내용 |
|---|---|
| 오늘 | 오늘 날짜(월·순) 기준, 내 작목의 **이번 순 작업 / 다음 순에 시작할 작업 / 재해 대비** |
| 작목 | 분류별 작목 목록·검색, ★로 내 작목 등록 |
| 작목 상세 | 재배 환경 기준 → 연간 농작업 달력 → 단계별 작업 방법 → 비료 주는 양(내 면적으로 자동 환산) → 병해충 → 기상재해 대책 → 원문 링크 |
| 달력 | 월을 고르면 그 달에 해야 할 작업을 작목별로 (내 작목/전체, 분류, 작업 종류 필터) |
| 계산기 | 면적 환산(㎡·평·a·10a·ha), 표준 시비량 × 내 면적, 성분량 → 비료 실물량·포대 수 |
| 일지 | 영농일지 기록, 연간 요약, CSV 내보내기, 백업/복원 |
| 더보기 | 농약안전정보시스템·병해충관리시스템·흙토람 등 바로가기, 자료 안내 |

가입·서버 없이 동작합니다. 내 작목·면적·일지는 사용자의 브라우저(localStorage)에만 저장됩니다. 홈 화면에 설치(PWA)할 수 있고, 한 번 열면 통신이 약한 곳에서도 열립니다.

## 실행

빌드 과정이 없는 정적 사이트입니다.

```bash
python3 -m http.server 8000
```

그대로 GitHub Pages 등 정적 호스팅에 올리면 됩니다.

## 구조

```
index.html              화면 틀
css/style.css           스타일 (밝은/어두운 테마, 모바일 우선, 인쇄용)
js/app.js               화면 로직 전부 (해시 라우팅, 의존성 없음)
data/crops/<id>.json    작목별 원자료 (id = 농사로 농작업일정 cntntsNo)
data/crops.json         위 파일들을 합친 번들 — 사이트는 이것만 읽음
data/SCHEMA.md          작목 데이터 형식
scripts/build-data.mjs  data/crops/*.json → data/crops.json
sw.js, manifest.webmanifest   오프라인·설치
```

작목 데이터를 고치거나 추가한 뒤에는 번들을 다시 만듭니다.

```bash
node scripts/build-data.mjs
```

## 자료 출처와 한계

- 모든 작목 데이터는 농사로 「농작업일정」 상세 페이지
  (`/portal/ps/psb/psbl/workScheduleDtl.ps?menuId=PS00087&cntntsNo=<id>`)에서 가져왔고, 작목마다 원문 링크가 붙어 있습니다.
- 원문에 없는 값은 채우지 않았습니다. 원문의 월별 작업 도표는 이미지/복잡한 표라 텍스트로 읽히지 않는 경우가 많아, **본문에 시기가 글로 적힌 작업만 달력에 표시**되고 나머지는 "시기 미표기 작업"으로 나옵니다.
- 수집은 페이지를 읽어 구조화하는 방식(자동 추출)이라 옮기는 과정의 오류가 있을 수 있습니다. 공개 전에 주요 작목은 원문과 대조 검수가 필요합니다.
- **이용 조건: 공공누리 제2유형 (출처표시 + 상업적 이용금지).** 유료 서비스·광고 등 상업적 이용을 계획한다면 농촌진흥청과 별도 협의가 필요합니다.

## 다음 단계

1. **농사로 Open API 연동** — 농사로 Open API(인증키 발급 필요)로 농작업일정·품종·병해충·주간농사정보를 정기 수집하면 달력의 빈 시기를 채우고 자료를 자동 갱신할 수 있습니다. API는 등록 도메인·서버 호출이 필요하므로 수집 스크립트(예: GitHub Actions)가 `data/crops/*.json` 을 갱신하는 구조를 권장합니다.
2. **날씨·기상특보 연동** — 필지 위치 기준 예보와 서리·폭염·호우 특보를 "오늘" 화면에, 작목의 재해 대책과 함께.
3. **영농일지 앱 연동** — 현재 일지 데이터(JSON)는 `id / date / crop / work / field / input / hours / cost / memo` 구조라 그대로 서버 동기화로 옮길 수 있습니다. 로그인, 기기 간 동기화, 사진 첨부, 농약 살포 기록(PLS 대응), 필지 관리.
4. **병해충·농약** — 작목별 등록 농약·안전사용기준(농약안전정보시스템), 병해충 발생 예보 연결.
5. **경영** — 일지의 비용·시간을 작목별 소득 분석으로, 농산물 소득자료·도매가격 연결.
